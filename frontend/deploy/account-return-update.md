# 聯絡方式、帳號管理與歸還時間更新

## 畫面

- 註冊、刊登、編輯刊登、帳號管理的聯絡方式都支援換行，每行可填一種方式，維持現有 100 字限制。
- 註冊依 API 第 2 版檢查 9 碼中央大學學號：年度 100 到台灣目前學年度（8 月切換）、學院 1–8、學制 0/2/3/5，其餘皆數字。這是格式驗證，不代表已驗證學生身分。
- 帳號管理可修改顯示名稱、聯絡方式及密碼，登入帳號唯讀。改密碼須填目前密碼與兩次新密碼；登入、註冊與改密碼均提供顯示／隱藏切換。
- 貼文聯絡方式留白時，使用帳號的最新聯絡方式；個別設定的聯絡方式不受帳號修改影響。
- 已歸還的照片上顯示年月日、時分秒（台灣時間），列表與詳細頁一致。

## API 與時間規則

- `PUT /api/auth/me` 需登入，支援部分更新 `display_name`、`contact`，或 `current_password` + `new_password`。僅更新目前登入者，忽略 `username`；無有效欄位、錯誤目前密碼、新密碼不足 6 字元回傳 400。成功後保持登入，回應不包含任何密碼。
- 貼文列表與詳細資料包含 `returned_at`（ISO 8601 或 null）。無時區的時間依 Asia/Taipei 解讀。
- 後端回傳的 `contact` 已含預設聯絡方式。編輯時會回填這個值；若要跟隨帳號聯絡方式，需將欄位清空。前端也相容選用的 `contact_override` 欄位，但不要求後端提供。
- 按「標記已歸還」送出既有 `PUT /api/posts/:id`，由伺服器在儲存狀態的當下記錄時間，避免用瀏覽器時鐘造成不同使用者看到不同時間。不必手動輸入。
- 重複標記或編輯其他欄位不改歸還時間；重新開放認領會清除時間，再歸還會記錄新的時間。
- 舊的已歸還貼文沒有可信時間，顯示「未記錄歸還時間」，不拿拾獲／更新時間代替。

## 部署順序

這次需要後端與資料庫一起更新，只部署前端無法儲存帳號資訊及歸還時間。

1. 後端同學拉取修改，在後端 Python 虛擬環境、原本的資料庫設定下執行：

   ```bash
   cd backend
   flask --app app init-db
   ```

   同學合併的新版 schema 會補上 `posts.returned_at TIMESTAMP`，可重複執行，不清空既有資料。
   若新版後端與欄位已上線，就不必重做此步驟。正式環境不要執行 `seed-db` 或 `smoke_test.py`。

2. 重新啟動後端 Flask/Gunicorn 服務。
3. 建置前端（`VITE_DATA_MODE=api`）並部署 dist 到 Nginx 站台。
4. 驗證修改個人資訊、重新登入、刊登多行聯絡方式、標記歸還後重新整理、重新開放認領。

純示範模式也支援這些操作，資料仍只保留於本次瀏覽。
